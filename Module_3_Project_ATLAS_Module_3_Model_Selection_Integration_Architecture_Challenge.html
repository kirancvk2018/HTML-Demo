Model Selection & Application Integration

Architecture decision lab · Workload fit, integration route, contracts and reliability
Scenario – GlobalTech Manufacturing

GlobalTech is piloting two Claude-powered capabilities: (1) a high-volume invoice field extraction service and (2) an engineering assistant that analyses long technical documents and synthesises multi-step findings. The organisation operates primarily on AWS, has strict credential controls, and needs an auditable integration. The design team must propose a model-selection method and an application integration pattern.

Important: No specific model name, price, context limit, latency figure or performance result is supplied. Do not invent one. Make evidence-based selection recommendations and identify what must be benchmarked.

Reference architecture principles

  1. Benchmark candidate models using representative examples and explicit acceptance criteria; do not choose by model name alone.
  2. Use a suitable capability level for each task. Extraction and complex synthesis may have different quality, latency, context and cost needs.
  3. Keep credentials and provider-specific integration logic in a trusted backend service.
  4. Choose the integration route based on platform strategy and verify availability, identity, quotas, networking and operational controls.
  5. Define request/response contracts. Parse, schema-validate and semantically validate outputs before downstream use.
  6. Use synchronous interaction for short caller-waited requests, asynchronous jobs for long-running tasks, and streaming when progressive output improves the experience.
  7. Use bounded retries, backoff, error classification, an evaluated fallback and a controlled failure path.
