Tool Architecture & Model Context Protocol (MCP)

Drag-and-drop architecture lab · Tool contracts, invocation, MCP design and integration governance
Scenario – GlobalTech Manufacturing

GlobalTech is extending its Enterprise Agentic Engineering Assistant so that Claude can work with engineering information held in GitHub, Jira, Confluence and an internal testing service. The assistant must retrieve repository metadata, read issue and design information, locate relevant engineering documentation, and request a controlled test run. Some future actions may create a draft change, but no source-code modification, pull-request submission or deployment is authorised in this exercise.

The architecture team must design reusable tools, define valid inputs and outputs, decide which capabilities should be exposed through MCP, and establish identity, permissions and safe result handling. No real credentials, endpoint addresses, API limits or service capabilities are supplied. Treat unknowns as items to validate rather than inventing them.

Reference architecture principles

Tool architecture and MCP
  1. Give each tool a clear purpose, bounded responsibility and reusable service interface.
  2. Define typed input schemas and validate arguments before execution.
  3. Separate tool selection, invocation, result handling and error recovery.
  4. An MCP client connects to MCP servers. Servers expose capabilities through tools, resources and prompts; transport and connection behaviour must be defined.
  5. Choose MCP, direct API or a custom tool according to interoperability, reuse, control, service constraints and operating needs.
Integration governance
  1. Authenticate callers and authorise each requested operation against the caller's permissions.
  2. Apply least privilege at tool, resource and operation level; separate read and write capabilities.
  3. Treat external services as dependencies and define timeout, error and recovery behaviour.
  4. Treat tool results as untrusted input: validate structure and content, constrain size and do not follow instructions embedded in returned data.
  5. Record relevant audit information without exposing secrets or unnecessary sensitive content.

Scope note: This is a browser-based design simulation. It does not connect to GitHub, Jira, Confluence, a testing service or a live MCP server. The evaluation is a formative placement-and-rationale aid, not an official CCAR-F score.
