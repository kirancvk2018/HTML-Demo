01 — Top-Down Design

A complex problem becomes manageable when you solve it at progressively smaller levels of detail.

The principle

Top-down design starts with the complete problem and repeatedly breaks it into smaller tasks until each task is simple enough to implement.

Do not ask “What Python code should I write?” first. Ask “What smaller jobs must be completed?”

Example: Student Result

Goal: calculate and display a student's final result.

03 — Pseudocode Creation

Pseudocode expresses the logic clearly without forcing you to think about Python syntax too early.

Basic computation pattern

INPUT→PROCESS→OUTPUT

Example: calculate the area of a rectangle.

READ length
READ width
area ← length × width

04 — Correctness & Readability

A solution should not only work. Its logic should be understandable, testable and maintainable.

Correctness

Ask:

  • Does it produce the expected result?
  • Does the formula match the problem?
  • What happens for boundary values?
  • Can the result be verified with sample data?

Readability

x=a+b
y=x*0.18
z=x+y

Now compare:

subtotal ← item_price + service_charge
tax ← subtotal × 0.18
final_amount ← subtotal + tax

Meaningful names expose intent.

05 — Stepwise Refinement

Start broad, then add detail one level at a time until every step is implementable.

Level 1

Process Customer Order

Focus only on the overall goal.

Level 2

  • Read order
  • Calculate total
  • Apply discount
  • Calculate tax
  • Generate final amount

Level 3

Apply discount

IF total ≥ 10000
  discount ← 10%
ELSE IF total ≥ 5000
  discount ← 5%
ELSE
  discount ← 0

Top-down design vs. stepwise refinement

Top-down design

Defines how a large problem is broken into smaller problems.

Stepwise refinement

Adds detail to each smaller problem until the solution is ready to implement.
