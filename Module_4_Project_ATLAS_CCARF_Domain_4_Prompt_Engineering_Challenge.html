Project ATLAS – Prompt Engineering & Structured Output Challenge

You are the Ness AI solution team. Assemble a reliable prompt-and-output design for an enterprise change-analysis workflow, submit it and review the feedback.

1. Client scenario

GlobalTech Manufacturing

GlobalTech is a multinational manufacturer with approximately 8,000 software engineers. Its OrderFlow Legacy application has incomplete documentation and complex dependencies. Engineering teams use Claude to analyse change requests and prepare structured recommendations.

A new change request states:

Change request: “Orders above a configurable threshold must undergo additional validation before acceptance. The threshold may vary by region.”

The AI workflow must analyse the request, identify missing information, propose investigation steps and return a machine-readable result for downstream review.

Known constraints

  • Do not invent regional thresholds, validation rules, APIs or database details.
  • Separate confirmed facts, assumptions and unresolved questions.
  • Return output that can be parsed and validated by software.
  • Flag ambiguity rather than silently choosing an interpretation.
  • Recommendations are advisory; an engineer approves consequential changes.
Your assignment: Assemble an enterprise-grade prompt design with explicit instructions, structured output, validation and controlled handling of missing information.

Think of the prompt as an interface contract: define the task and trusted inputs, constrain unsupported claims, specify a schema, and validate both structure and meaning. Valid JSON can still contain an incorrect business conclusion.

3. Prompt and output reasoning questions

Discuss these questions before or after submitting.

  1. Why is a specific task definition more useful than a broad persona instruction alone?
  2. How should the prompt distinguish confirmed facts, assumptions and missing information?
  3. Why is a JSON schema necessary, and why is schema validation not sufficient?
  4. When would few-shot examples improve consistency? What risks arise from poorly chosen examples?
  5. What should the application do when the model returns malformed JSON or a semantically invalid result?
  6. Where should human review occur, and which decisions must remain outside autonomous execution?
Project ATLAS is a fictional learning scenario. The reference design is an instructional example, not a prescribed Anthropic or Ness production prompt.
